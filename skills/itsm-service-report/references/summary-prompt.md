# 服务总结 prompt（三段结构 + 字体粗细标注）

> SKILL.md 第 7 步引用。输入结构化数据（下方契约），输出**带 `**加粗**` 标记的三段连续文本**，写入输出文件 `A7:J8` 合并区（A–J 列，K7:M8 留给饼图）。执行期由 SKILL.md 第 7 步把 `**...**` 解析为富文本 runs（bold=true/false）写入——**不要输出 JSON、段号、markdown 围栏**。
> **风格范本**：`template.xlsx` 的 A7 是得力客户 2025 年度真实服务总结，三段结构成熟——仿其基调与句式（感谢信任 → 零重大故障/主动巡检/完成率 → 按类别占比"服务聚焦+价值体现"），但**类别用 spec 固定 5 大类**，不用模板的细分类。

## 输入数据契约

执行期 Claude 收集以下字段，连同本 prompt 提供给 LLM：

```json
{
  "project": "项目名（原始 A3）",
  "dateRange": "日期段（原始 A4 提取，如 2025.08.08-2026.08.07）",
  "totalTickets": 104,
  "doneTickets": 95,
  "pendingTickets": 9,
  "requesters": 12,
  "doneRate": "91.3%",
  "categoryCounts": {"需求与性能优化":20,"服务器健康检查":8,"服务故障处理":35,"问题咨询":30,"BUG问题":11},
  "topContacts": ["吴锦涛","张三","李四"],
  "majorIncident": false,
  "guidance": "用户给的导向描述，没有则为空字符串"
}
```

- `categoryCounts` = 5 类固定枚举（需求与性能优化 / 服务器健康检查 / 服务故障处理 / 问题咨询 / BUG问题）的计数 dict。**计数为 0 或缺失的类别一律忽略**——总结第 3 段不写、饼图不画（SKILL.md 第 8 步同规则）。
- `doneRate` = round(doneTickets/totalTickets*100, 1) + "%"。
- `majorIncident` = 扫描全部工单主题是否含 `P0 / 宕机 / 重大 / 严重故障 / 数据丢失` 任一关键词；命中为 true。
- `topContacts` = 创建人按频次 top 1–3，**先清洗前缀**：去掉 `公司名_` / `部门_` / `系统_` 等下划线前缀（如 `优特格尔_吴锦涛`→`吴锦涛`、`得力_王梦杰`→`王梦杰`、`SIE_周俊`→`周俊`）；纯英文/数字账号保留原样并标注。

## 字体粗细标注规则（核心，务必遵守）

输出文本用 `**...**` 标注**加粗**片段，未标注的均为常规。执行期按 `**...**` 边界切分为 richtext runs——**每个 run（无论 bold 与否）由执行期统一注入字体** `{"font":"微软雅黑","size":"16pt","color":"000000"}`（与模板 A7 字体一致）。LLM 只负责 `**...**` bold 标记，**不关心字体/字号/颜色**（字体注入理由见 template-anatomy"服务总结富文本"章节：officecli 写 richtext 会重建 styles，runs 不能靠继承单元格样式拿字体）。

**以下一律用 `**...**` 包裹（加粗）：**
- 区块大标题：`**服务总结：**`、`**服务概览：<四字基调副标题>**`（如"稳健护航，成效显著"）。
- 服务概览下的小标题：如 `**系统稳定性卓越，风险可控：**`、`**服务响应及时，闭环管理：**`（仿范本，按实际成果组织）。
- 成果要点标签：`**零重大故障：**`、`**主动预防巡检：**`、`**工单完成率<N>%：**` 等"标签："形式。
- 工单类型分布引导句：`**服务工单类型分布：<引导句>：**`。
- 每类标题行：`**<类别>（<n> 件，占 <pct>%）：**`（固定类名；只写计数 > 0 的类，0 计数类整类不出现）。
- 每类下的子标签：`**服务聚焦：**`、`**价值体现：**`。

**以下不加标记（常规）：** 所有描述性正文句子（感谢词、数据陈述、服务聚焦/价值体现的具体内容、过渡句）。

> 标注示例片段：
> `**服务总结：**\n衷心感谢贵司团队…信任与支持。\n**服务概览：稳健护航，成效显著**\n本周期共处理工单 104 件…\n**系统稳定性卓越，风险可控：**\n**零重大故障：** 全年未发生…\n**需求与性能优化（20 件，占 19.2%）：**\n**服务聚焦：** 针对…\n**价值体现：** 提升了…`

## 输出：三段（仿模板基调，客户运维服务报告正式风格）

**第 1 段 · 开篇感谢 / 概述（2–4 句）**
- 仿"衷心感谢贵司团队…对我方运维服务的信任与支持"句式，说明本报告覆盖 `<dateRange>` 的运维服务。
- 以 `**服务总结：**` 起头（加粗），紧跟换行，正文常规。
- 提及主要联系人：`在本周期内，主要与 <topContacts> 保持紧密沟通协作（特别感谢…老师们及时反馈与协调）。`
- 若 `guidance` 非空：把导向描述作为基调融入开篇（如用户要"突出主动服务"，则点出主动巡检/快速响应）。

**第 2 段 · 服务概览（数据驱动，3–5 句）**
- 以 `**服务概览：<四字基调副标题>**`（加粗）起头，换行后正文常规。
- 仿"系统稳定性卓越，风险可控 / 服务响应及时，闭环管理"结构，每个小标题用 `**...：**` 加粗。
- 数据句（常规正文）：`本周期共处理工单 <totalTickets> 件，完成 <doneTickets> 件，完成率 <doneRate>，服务请求人数 <requesters>。`
- 故障声明（`**零重大故障：**` 加粗标签 + 常规正文）：`majorIncident=false` → `零重大故障：期间未发生 P0 级重大停机事件，保障了业务连续性`；`true` → 如实列出重大事件（不掩饰）。
- 主动服务：若 `服务器健康检查` 计数 > 0，用 `**主动预防巡检：**` 加粗标签 + 常规正文"完成 N 次主动巡检/健康检查，提前识别潜在风险"。

**第 3 段 · 工单类型分布（只写计数 > 0 的类，按占比降序）**
- 以 `**服务工单类型分布：<引导句>：**`（加粗）起头。
- 逐类写：`**<类别>（<n> 件，占 <pct>%）：**` 加粗标题行 + 换行 + `**服务聚焦：**<内容>` + 换行 + `**价值体现：**<内容>`（子标签加粗、内容常规；**服务聚焦、价值体现各自独立一行，不以分号连在同一行**——否则视觉上挤在一起，客户常需手动补换行）。
- **只写 `categoryCounts` 中计数 > 0 的类别**（按占比降序）；**计数为 0 或缺失的类别整类不出现**——不写"无该类工单"之类占位，饼图也不画（SKILL.md 第 8 步同规则）。
- 类别名用固定 5 类名（需求与性能优化 / 服务器健康检查 / 服务故障处理 / 问题咨询 / BUG问题），不自创分类名；只是不呈现 0 计数类。

## 规则

- 全程简体中文，正式基调；不夸大、不编造未在数据中出现的事实。
- 数字必须与输入契约完全一致（不得自行四舍五入到不一致）。
- 呈现类别（计数 > 0 的那些）占比之和若因四舍五入 ≠ 100%，末尾注"占比经四舍五入，合计可能非 100%"（此句常规）。
- 直接输出三段连续文本（段间空行），**只用 `**...**` 做加粗标记**，不输出 JSON、段号、markdown 围栏（```），便于执行期直接解析为 runs 写入 A7:J8。
- `guidance` 为空时按通用基调生成，不提"根据您的要求"之类元话语。
- 换行用真实 `\n`（段落之间、标题与正文之间都要换行，便于阅读）。

## 降级

LLM 生成失败 → SKILL.md 回退"数据驱动最小版"：仅第 2 段统计句 + 第 3 段对每个**计数 > 0** 的类写一句"`**<类别> <n> 件（<pct>%）**`"（0 计数类不写），不含润色段落，仍保留 `**...**` 加粗标记，并在交付报告标注"服务总结为降级最小版"。
