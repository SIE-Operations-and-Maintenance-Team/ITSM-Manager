# 工单分类 prompt（5 大类）

> SKILL.md 第 4 步引用。每批 ~20 条工单套用本 prompt。固定 5 类，不得新增/改名。
> 输入只用「主题 + 解决方案」，**不信任原始导出的"服务目录"列**（实测该列常批量填同一个值如 BUG问题，严重失真）。

## 类别定义（固定枚举）

| 类别 | 定义 | 典型信号（主题/解决方案中出现） |
|---|---|---|
| 需求与性能优化 | 用户新增/变更功能、性能调优、容量扩展、并发改造、部署自动化建设、为改善体验的配置调整 | "优化""调优""扩容""并发""性能""卡顿/慢""缩短时长""自动部署/发布""新增/希望增加" |
| 服务器健康检查 | 巡检、监控、资源检查、预防性维护、安全漏洞修复/加固、系统体检、定期报告 | "巡检""体检""监控""健康""漏洞修复""弱口令""防火墙/iptables""磁盘检查""预防" |
| 服务故障处理 | 系统宕机、功能不可用、报错、异常、数据问题、服务/组件异常等需紧急恢复 | "异常""宕机""不可用""告警""报错""失败""磁盘超90%""会话数暴增""数据丢失""服务无法启动" |
| 问题咨询 | 使用疑问、操作指导、业务规则解答、配置咨询、文档索取、how-to | "如何""怎么""咨询""请问""能否""规则""指导""不明白""远程调试确认" |
| BUG问题 | 确认的程序缺陷/功能错误，需代码修复（"应正确却错了"）。与"需求"区分：缺陷是修坏，需求是做新 | "缺陷""bug""报错且定位到代码""与预期不符""状态不一致""重复/重复推送""修正代码""签入" |

## 判断优先级（自上而下，命中即止）

1. 主题/解决方案明确含**故障/宕机/异常/告警/不可用/数据错误/资源超限**（如磁盘>90%、会话暴增）→ **服务故障处理**
2. 明确含**巡检/体检/监控/漏洞修复/弱口令/防火墙/安全加固**（主动预防性）→ **服务器健康检查**
3. 明确含**咨询/疑问/操作指导/业务规则/配置怎么配**（how-to，非修坏也非做新）→ **问题咨询**
4. 明确是**程序缺陷**（应正确却错误，解决方案是"修代码/已签入/状态不一致/重复推送"等）→ **BUG问题**
5. 明确是**新功能/性能/并发/容量/部署自动化**诉求（做新或优化）→ **需求与性能优化**
6. 信号冲突或信息不足 → 输出 `confidence=low`，SKILL.md 会用 `get_ticket_by_code` 查详情后二次判断

> 易混点：
> - **BUG vs 需求**："收货等待时间长，优化代码处理" → 是优化（需求与性能优化）；"库存状态不一致，已修正代码签入" → 是缺陷修复（BUG问题）。看是"做新/优化"还是"修坏"。
> - **故障 vs BUG**：故障强调"正在影响业务、需紧急恢复"（宕机/告警/超限）；BUG 强调"功能逻辑错误，修代码"。同一报错，若主题含"宕机/告警/超90%"偏故障；含"状态不一致/重复"偏BUG。拿不准时优先按主题的紧急程度判。
> - **漏洞修复 → 服务器健康检查**（主动安全加固、预防性），除非漏洞已造成在用故障（→ 服务故障处理）。

## 输入格式（每批）

收到一个 JSON 数组，每项：`{"code":"IM单号","subject":"主题","solution":"解决方案"}`。

## 输出格式（严格，便于解析）

仅输出 JSON 数组，每项：
```json
{"code":"IM26070065","category":"服务故障处理","confidence":"high","reason":"主题含'影响业务数据'/'幽灵任务'，紧急恢复"}
```
- `category`：必须是上表 5 类之一，**原样照抄类别名**（如"BUG问题"含"问题"二字，照抄）。
- `confidence`：`high`（信号明确）/ `medium`（有信号但偏弱）/ `low`（冲突或信息不足，需查 ITSM 详情）。
- `reason`：≤30 字，引用命中的信号词。
- 不要输出任何 JSON 以外的文字、不要包 markdown 代码围栏。

## 降级（SKILL.md 编排，非本 prompt 内容）

- `confidence=low` 的工单 → SKILL.md 用 itsm-tools `get_ticket_by_code(code)` 取描述+历史回复，把补充信息并入 subject+solution 重跑本 prompt。
- itsm-tools 不可用 → 跳过详情查询，按现有信息给 best-guess 分类并在报告中标注降级。
- 仍 `low`（查详情后还不确定）→ 归 **BUG问题** 并把单号列入"存疑清单"写进交付报告。
